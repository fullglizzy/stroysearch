# План: админ-управление пользователями + бан с причиной

## 1. База данных
- `prisma/schema.prisma`: добавить `banReason String?` в модель `UserServiceFields`.
- `npx prisma migrate dev --name add_ban_reason` (sqlite, ALTER TABLE — без потери данных).

## 2. Бан при логине
- `src/lib/auth.ts` (authorize): переставить проверки — сначала пароль, потом статусы. Если пароль верный и `status === "BANNED"` — бросить `class BannedUserError extends CredentialsSignin { code = "banned" }` (next-auth v5 пробрасывает кастомный `code` в `result.code` клиента — подтверждено чтением исходников beta.32). DELETED — как раньше `null`.
- Новый публичный роут `src/app/api/auth/ban-info/route.ts`: POST `{username}` → `{ banned: true, reason }` или `{ banned: false }`.
- `src/app/(auth)/login/page.tsx`: при `result.code === "banned"` — показать «Аккаунт заблокирован. Причина: …» (причину взять из ban-info), иначе прежняя ошибка «Неверный логин или пароль».

## 3. Админ-API (только SUPER/ROOT, по паттерну `api/admin/coins`)
- `GET /api/admin/users/[id]` — полная инфа аккаунта: user + profile(roles) + wallet + serviceFields + company(metrics) + admin + счётчики (отзывы получено/оставлено, документы, конференции, товары).
- `POST /api/admin/users/[id]/ban` — `{ reason }` обязательна (1–500 симв.): `status=BANNED` + `banReason` (upsert serviceFields). Запреты: нельзя банить себя и ROOT.
- `POST /api/admin/users/[id]/unban` — `status=ACTIVE`, `banReason=null`.

## 4. Страница /admin/users — фильтры (сервер, searchParams)
- Расширить `where`: `q` (+ ФИО), `status`, `type`, `region` (profile.region), `role` (profile.roles.some), сортировка (`created` / `name`).
- В выборку добавить `serviceFields` (banReason) и регионы из `getRegions()` для фильтра.

## 5. UsersManager (клиент) — UI
- Панель фильтров: поиск (есть) + Select статуса + Select типа + Select роли + SearchSelect региона + «Сбросить» (паттерн `updateQuery` + router.replace, как в Suppliers/Matrix клиентах).
- Клик по строке пользователя → попап: данные подгружаются с `GET /api/admin/users/[id]` и рендерятся по роли:
  - общее: логин, email, телефон, статус, дата регистрации, баланс, причина бана (если есть);
  - участник: ФИО, ник, регион, роли (через `roleLabel` из `src/lib/roles.ts`), скрытие контактов;
  - компания: ИНН, название, КПП, юр. адрес, директор, сайт + метрики просмотров (5 счётчиков);
  - админ: adminType, permissions;
  - активность: счётчики отзывов/документов/конференций/товаров.
- В попапе: «Забанить» (поле причины) / «Разбанить» → POST API → обновление данных. Кнопка «Монеты» остаётся.
