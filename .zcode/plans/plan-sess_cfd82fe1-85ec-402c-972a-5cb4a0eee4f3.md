# Дерево решений: ультра-удобное редактирование + undo/redo + безопасное сохранение

## Что выяснил (ключевые факты)
- Узлы ссылаются из контента по **UUID** (`Product.treeItemId`, `LibraryDocument/Conference/Poll.treeItemId`, `classifierIds` у профилей/компаний) — значит переименование/перенумерация/смена родителя **автоматически отражаются везде** через join. Ломается только то, что хранит **пути-строки**: URL-фильтры `/matrix?classifier=<путь>` и `/library?classifier=<путь>`, фильтр категорий и reverse-lookup в `ProductsManager` (value = fullNumberPath).
- Серверная перенумерация сейчас без транзакций, с риском «частичной» перенумерации и двусмысленных позиций при move. Move/reorder не подключены к UI. DnD нет (мёртвый импорт GripVertical).
- Удаление — мягкое, рекурсивное, **без проверок**: товары под удалённым узлом исчезают из матрицы, документы/конференции/опросы остаются с «замороженным» путём, профили — с висячими UUID.

## 1. Движок дерева (сервер) — переписываю ядро `src/server/admin/tree.ts`
- **Один атомарный batch-эндпоинт** `POST /api/admin/tree/batch`: массив операций `{ type: "create"|"update"|"move"|"delete"|"restore", id, name, description, bannerUrl, parentId, position }` применяется **в одной транзакции**:
  - операции применяются к JS-модели всего дерева (без промежуточных записей в БД → не бывает «частичной» перенумерации);
  - затем **полная перенумерация всего живого дерева** в JS: порядок = позиции из операций + текущий порядок, `inBranchNumber` 1..N и `fullNumberPath` пересчитываются рекурсивно;
  - в БД пишутся только изменившиеся узлы (bulk), внутри транзакции.
- **Защита целостности**:
  - циклы: нельзя назначить родителем себя/потомка; нельзя в удалённый узел;
  - **удаление с контентом блокируется**: сервер считает привязанные товары/документы/конференции/опросы + **ссылки из `classifierIds` профилей и компаний** (LIKE по CSV) и возвращает понятную ошибку со счётчиками («Сначала перенесите содержимое») — удалить можно только пустой узел.
- Существующие одиночные роуты (`POST /api/admin/tree`, `PATCH/DELETE /api/admin/tree/[id]`) оставляю как тонкие обёртки над тем же ядром (совместимость).

## 2. Новый TreeConstructor (клиент) — черновое редактирование с undo/redo
Полный рерайт `src/components/forms/TreeConstructor.tsx`:
- **Черновик**: правки применяются к локальной копии дерева, сервер не трогается до подтверждения.
- **Undo/Redo**: стек истории операций (каждая правка кладёт обратную операцию); кнопки в панели + горячие клавиши Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z. Новая правка очищает «redo».
- **Панель изменений**: «Изменений: N · Отменить · Повторить · Применить изменения». «Применить» открывает **подтверждение со списком изменений** («Переименовать X→Y», «Переместить A под B», «Удалить C и поддеревья»…), после подтверждения — один POST batch → тост → свежее дерево с сервера, история очищена.
- **Удобное редактирование**:
  - инлайн-переименование по клику на название (Enter/blur);
  - «+ Дочерний», редактирование (название/описание/баннер/родитель) в диалоге, восстановление удалённых;
  - **стрелки ↑/↓** для порядка внутри родителя (перенумерация пересчитается на сервере);
  - **drag&drop** нативный (без библиотек): перетаскивание узла — подсветка валидных целей, бросок на узел = стать его последним ребёнком, бросок на корневую зону = в корень; перетащить в собственное поддерево нельзя;
  - **поиск по дереву** (фильтр с подсветкой совпадений), **развернуть/свернуть всё**;
  - счётчики контента: товары/документы/конференции/опросы у каждого узла; у удалённых — кнопка «Восстановить».
- Удаление: в диалоге показываются счётчики привязанного контента; если есть — предупреждение, сервер всё равно блокирует.

## 3. Распространение изменений на всё, что использует узлы
- Переименование/перенумерация/смена родителя — уже распространяется автоматически (все ссылки по UUID).
- **Убираю хранение путей как значений** там, где это ломается:
  - `/matrix` и `/library`: URL-параметр `classifier` переходит на **id узла** (`t.id IN (…)`), опции фильтров и ссылки в публичном дереве `ProductTree` — `value: id` (label «путь — название»). Старые закладки с путями перестанут работать (это осознанная плата за надёжность).
  - `ProductsManager` и страницы товаров (admin/company): фильтр категорий и выбор категории при редактировании — по **id** (в `ProductRow` добавляю `treeItemId`).
- После сохранения батча всё (товары, матрица, библиотека, профили) мгновенно показывает новые номера/названия через join — дополнительных миграций не нужно.

## 4. Дополнительные улучшения (включил)
- В счётчики узлов добавлены конференции и опросы (сейчас только товары/документы).
- Валидация `treeItemId` в API товаров/документов/конференций/опросов: запрет создания на удалённый/несуществующий узел (защита от «невидимых» товаров в матрице).
- Висячие `classifierIds` в профилях: при удалении узла теперь невозможно (guard), а существующие висячие id при сохранении профиля продолжают вычищаться (текущее поведение).
