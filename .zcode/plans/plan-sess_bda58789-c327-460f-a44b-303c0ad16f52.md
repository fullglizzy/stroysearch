# Переделка /admin/finances: счета по произвольной дате + массовое выставление + тариф на странице + отмена и перевыставление

## Суть новой модели
Админ выбирает ОДНУ дату; счёт покрывает весь невыставленный период: от водяной отметки (billedThrough+1 или billingStartedAt) до этой даты включительно — в него попадают все накопленные просмотры и абонплата за все дни. Гейт «завершённый месяц» (isPeriodCompleted) и привязка к концу календарного месяца убираются. Миграций БД не нужно — водяная отметка billedThrough уже хранит произвольную дату.

## Сервер

### src/lib/billing.ts
1. `buildBillingItems`: убрать ограничение `Math.min(maintenanceDays, daysInMonth)` — абонплата теперь копится за весь период с последнего счёта (пропорция по дням, делитель daysInMonth сохранить).
2. `createBillingInvoice`: добавить опциональные параметры `ratesOverride` (частичные ставки поверх effectiveRates — для перевыставления) и `counts` (готовые счётчики, чтобы не считать дважды при массовой генерации); `date = periodTo`, `dueDate = periodTo + invoiceDueDays` (вместо «сейчас») — счёт датируется выбранной датой.
3. `generateBillingInvoices`: `periodTo` по умолчанию = сегодня; период всегда «от водяной отметки до endOfDay(periodTo)»; убрать `nextBillingPeriod` и `isPeriodCompleted`; skip при `from > to` («Нет периода для выставления») и при `subtotal = 0` («Нет начислений за период»); массовая ветка предсчитывает counts/subtotal до транзакции, чтобы не создавать пустые счета.
4. Удалить ставшие мёртвыми `nextBillingPeriod`, `isPeriodCompleted`, `monthBounds` (после замены всех использований).

### src/app/api/admin/billing/invoices/route.ts (POST)
Сигнатура не меняется (`{companyId|companyIds, periodTo}`) — поведение меняется внутри `generateBillingInvoices`. GET (список, фильтр по месяцу) не трогаем.

### src/app/api/admin/billing/invoices/preview/route.ts
Переделать на дату: `periodTo` (по умолчанию сегодня), период от водяной отметки до endOfDay(date), убрать гейт завершённости (строки 83–90); skip при `subtotal = 0`. Ответ уже содержит companyId, period, items, subtotal — используется диалогом массового выставления.

### src/app/api/admin/billing/invoices/[id]/route.ts (PATCH)
- `cancel`: разрешить для DRAFT, SENT, OVERDUE (сейчас только DRAFT). Гард: отменять можно только ПОСЛЕДНИЙ неотменённый счёт компании (нет более поздних неотменённых с billedThrough > данного) — иначе при следующем выставлении метрики задвоятся. Откат водяной отметки к предыдущему неотменённому счёту — как сейчас.
- Новое действие `reissue` (для SENT/OVERDUE): тело `{date?, rates?{6 ставок+monthlyCap}, saveRates?}`. В одной транзакции: тот же гард «последний счёт» → старый счёт CANCELLED → откат водяной отметки → при `saveRates` обновить CompanyBilling → создать новый счёт `createBillingInvoice` с `ratesOverride` (дата по умолчанию = periodTo старого, не позднее сегодня) → уведомление владельцу («Счёт N отменён, выставлен новый M»). Ответ `{success, created:{id, number, total}}`.
- Остальные действия (send/pay/skip/edit) без изменений.

### src/app/api/admin/companies/[id]/billing/route.ts (GET)
Добавить query-параметр `?date=` (по умолчанию сегодня): период = водяная отметка+1 (или billingStartedAt) → endOfDay(date); preview/viewsInPeriod считаются для этой даты. Убрать `periodCompleted` из ответа. PUT не меняется.

### src/app/api/billing/my/route.ts (кабинет компании)
Предпросмотр «следующего месяца» заменить на «накоплено к выставлению»: период от водяной отметки до сегодня. В `CompanyBillingOverview.tsx` поправить подпись периода.

## Клиент

### src/components/forms/billing/CompanyTariffsManager.tsx (главный файл)
1. **Панель тарифа НАД таблицей** (вместо секции в попапе): при клике по строке таблицы компания выбирается (подсветка строки), над таблицей появляется карточка «Тариф компании: {name}»: 7 полей ставок (автосохранение с debounce 600 мс и индикатором «Сохранение…/Сохранено ✓/Ошибка» — паттерн из попапа), статус биллинга + причина скрытия + кнопка «Сохранить статус», кнопка «Закрыть». Данные — из расширенного ответа списка (billing + defaults), без запроса. Кнопка «Открыть» в строке сохраняет поведение попапа (stopPropagation).
2. **Кнопка «Массово выставить счета» рядом с панелью** (в той же панели над таблицей): открывает новый диалог.
3. Попап: убрать секцию «Тариф и статус» и весь rates-стейт. Секция «Начисления за период» → «Начисления до даты»: `<input type="date">` (max = сегодня, по умолчанию сегодня), предпросмотр через `GET .../billing?date=` (перезапрос по debounce при смене даты): период, разбивка просмотров, позиции, итог; кнопка «Сформировать счёт» (POST `{companyId, periodTo}`), скрыта при subtotal = 0, при статусе ≠ ACTIVE — подсказка. Убрать сообщения про «период ещё не завершён» и поле periodCompleted из типов.

### src/components/forms/billing/MassInvoiceDialog.tsx (новый файл)
