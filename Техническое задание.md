# План реворка вкладки «Финансы» (админка)

Дата: 2026-08-21 · Статус: на утверждение · Редакция 2 — добавлены требования: простота для администратора без технической подготовки, масштаб (тысячи компаний), заметки, учёт регистраций и оплат, выдача пароля, бан.

## 1. Цель

Переделать вкладку «Финансы» в админке так, чтобы:

1. **Все действия выполнялись вручную** — ни счета, ни санкции, ни восстановление контактов не происходят сами. Каждый шаг администратор делает явной кнопкой и понимает его результат.
2. **Компания стала центральной сущностью**: главный экран показывает общую ситуацию (KPI + сводная таблица по всем компаниям), а по каждой компании есть **один информативный попап** со всей ситуацией и всеми действиями.
3. **Каждая кнопка и статус понятны без инструкций**: короткие подписи, пояснения в диалогах подтверждения, легенда статусов.
4. **Интерфейс рассчитан на администратора без технической подготовки**: простые слова вместо терминов, диалоги, объясняющие последствия действия, минимум кнопок на экране, понятные цвета-бейджи.
5. **Масштаб — тысячи компаний**: таблицы с серверной пагинацией, поиском и фильтрами; сводные цифры считаются в базе, а не в браузере.
6. **Полный учёт компаний**: видно, кто и когда зарегистрировался, кто платит, а кто нет; по каждой компании есть заметки администратора; новому владельцу выдаётся пароль; при необходимости владелец блокируется (бан).

## 2. Что сейчас мешает (проблемы)

| Проблема | Следствие |
|---|---|
| Статус «Приостановлен» (PAUSED) | Существовал только ради автоформирования счетов. Раз всё вручную — статус только путает: админ не понимает, зачем нажимать «Паузу», если счета он и так создаёт сам. |
| Cron автоматически формирует счета | Противоречит «всё вручную»: счета могут появиться «сами», непонятно откуда. |
| Главная вкладка — список счетов | Админ мыслит «по компаниям»: сколько должна компания, что начисляется, что с её счетами. Сводки по компании нет в одном месте. |
| Попап «Тариф» | Показывает только ставки; долг, счета и акты компании приходится искать в других вкладках. |
| Отдельная вкладка «Обзор» | Дублирует роль главного экрана; KPI размазаны по вкладкам. |
| Список компаний ограничен 300 строками, поиск и фильтры — в браузере | С тысячами компаний не работает: старые компании выпадают из списка, неплательщиков не найти, интерфейс тормозит. |
| Нет заметок о компаниях | Некуда записать «зарегистрировался по телефону», «договорились об отсрочке», «ИНН не проверили», «просил звонить после 18:00». |
| Не видно, кто платит, а кто нет | Долг спрятан в отдельных счетах; нет отметки «Платит / Не платит» и фильтра по ней. |
| Не видна дата регистрации | Нельзя понять, давно ли компания на платформе. |
| Выдача пароля и бан разбросаны | Пароль выдаётся в одном диалоге, бан — во вкладке «Пользователи»; админ теряется между экранами. |

## 3. Целевая модель

### 3.1. Статусы компании (3 вместо 4)

- **Активна** — биллинг идёт: администратор может формировать счета, просмотры контактов считаются и тарифицируются.
- **Контакты скрыты** — санкция за неуплату: телефон/почта/сайт скрыты в базе поставщиков, новые просмотры не считаются. Применяется и снимается только вручную, с указанием причины (видна компании).
- **Без владельца** — биллинг выключен, компания бесплатна; для включения нужно выдать доступ владельцу.

Статус **«Приостановлен» удаляется полностью** (схема — только комментарий, миграция не нужна, поле String).

### 3.2. Структура вкладки (4 вкладки)

1. **Компании** (открывается по умолчанию)
   - сверху — KPI-карточки: долг всего, выставлено за месяц, просрочено, просмотры за месяц, компаний без владельца;
   - ниже — сводная таблица по всем компаниям (с пагинацией, поиском и фильтрами, см. 3.5);
   - клик «Открыть» — информативный попап компании.
2. **Счета и акты** — только просмотр и работа с готовыми счетами: фильтры (статус, поиск, месяц периода), действия «Выставить / Оплачен / Пропустить / Отменить / Скидка», печать, секция актов. Счета здесь **не формируются** — их создаёт администратор в попапе компании (вкладка «Компании»).
3. **Метрики** — журнал просмотров по компаниям (без изменений).
4. **Настройки и подарки** — экономика, ставки по умолчанию, редактирование строк шаблонов счетов и актов, подарки.

### 3.3. Рабочий процесс (полностью ручной)

1. Админ открывает «Компании», видит долги и статусы.
2. Открывает попап компании → видит начисления за завершённый период → «Сформировать счёт за период» (единственное место формирования счетов).
3. В «Счета и акты» — «Выставить» (компания получает уведомление в кабинете).
4. Деньги пришли → «Оплачен» → автоматически создаётся **только акт** (документ-следствие оплаты, не действие).
5. Не платит → срок оплаты истекает, счёт **автоматически** становится «Просрочен» → администратор применяет «Скрыть контакты» (санкция с причиной, только кнопкой).
6. Оплатил после санкции → «Вернуть контакты» (вручную).
7. Никакого автоформирования счетов и авто-восстановления контактов нет.

### 3.4. Простота для администратора (принципы)

- **Кнопки называют действие целиком**: «Сформировать счёт», «Выставить счёт», «Отметить оплату», «Скрыть контакты», «Вернуть контакты», «Заблокировать владельца», «Создать владельца и показать пароль» — без аббревиатур (в интерфейсе «Просрочен», а не OVERDUE).
- **Каждое необратимое действие — диалог подтверждения** на 1–2 предложения простым языком: что произойдёт и как это отменить. Там, где нужна причина (скрытие контактов, бан), — обязательное поле «Причина» с подсказкой, зачем она.
- **Легенда статусов прямо над таблицей**: цветной бейдж + одна строка текста, что он означает.
- **Цвета помогают**: долг и «Не платит» — красным, «Платит» — зелёным, «Без владельца» — серым. Не полагаться только на цвет — рядом всегда текст.
- **Один экран — одна задача**: сводка и работа с конкретной компанией — на «Компании»; массовые действия со счетами — на «Счета и акты».
- **Пустых состояний нет**: если долгов нет, KPI показывает «0 ₽» с пояснением, а не пустоту.

### 3.5. Масштаб: тысячи компаний

- **Серверная пагинация** таблицы компаний: 25 / 50 / 100 строк на страницу, счётчик «Показаны 1–50 из 1234», кнопки страниц.
- **Поиск** по названию, ИНН, логину и email владельца (запрос на сервер с задержкой ввода).
- **Фильтры**: статус (все / Активна / Контакты скрыты / Без владельца), оплата (все / Платит / Не платит), есть/нет владельца.
- **Сортировка** по клику на колонку; по умолчанию — по долгу по убыванию: неплательщики всегда сверху.
- **KPI считаются агрегатами в базе** (сумма долга, просрочено, просмотры за месяц), не в браузере.
- API отдаёт только страницу: `{ companies, total, page, perPage }`.
- Таблица счетов («Счета и акты») — та же схема: проверить пагинацию, при отсутствии добавить.
- Поиск по кириллице в SQLite (LIKE там чувствителен к регистру) — через служебную колонку `searchText` (имя + ИНН в нижнем регистре, обновляется при создании/переименовании); логин и email владельца — латиница, ищутся обычным LIKE.

### 3.6. Заметки администратора о компании

- Новая таблица `CompanyNote`: `id`, `companyId`, `text`, `createdAt` (дата проставляется автоматически; авторы не нужны — заметки пишет только админ).
- В попапе компании — секция «Заметки»: поле ввода + кнопка «Добавить», ниже список заметок с датами; каждую заметку можно удалить (с подтверждением).
- В таблице компаний — индикатор числа заметок в строке (например, «📝 3»), чтобы было видно, за какой компанией нужно следить.
- Требуется миграция БД (новая таблица).

### 3.7. Учёт компаний: регистрация и оплата

- Колонка **«Регистрация»** — дата создания компании (формат «21.08.2026»); в попапе дополнительно дата регистрации владельца.
- Колонка **«Оплата»** — бейдж «Платит» / «Не платит» / «—». Правило:
  - **«Платит»** — нет долга и нет просроченных счетов;
  - **«Не платит»** — есть долг или хотя бы один просроченный счёт;
  - **«—»** — биллинг ещё не начат (нет ни одного BILLING-счёта) или у компании нет владельца.
- Фильтр по этой колонке — главный инструмент «кто платит, а кто нет».
- Колонка **«Владелец»** дополняется статусом аккаунта (Активен / Забанен / —).

### 3.8. Доступ: пароль новым пользователям и бан

- **Выдача пароля**: в попапе компании (быстрое действие «Доступ», когда владельца нет) — «Создать владельца»: логин + email + пароль. Пароль можно ввести самому или нажать «Сгенерировать» (система создаёт надёжный). После создания пароль показывается **один раз** крупно, с кнопкой «Скопировать» и предупреждением «Передайте пароль владельцу — повторно он показан не будет». Админ передаёт логин и пароль компании любым способом (телефон, почта).
- Сохраняются и остальные пути регистрации (компании регистрируются по-разному): самостоятельная регистрация и регистрация по ссылке-приглашению. Все пути сходятся в одну таблицу с датой регистрации. Режим «Привязать существующего пользователя» убран — владелец получает доступ через создание аккаунта с паролем или ссылку.
- **Бан владельца**: в секции владельца попапа — «Заблокировать» (обязательная причина, она видна пользователю при входе) / «Разблокировать». Заблокированный владелец не может войти; компания при этом остаётся в таблице, у неё виден статус владельца «Забанен». Механика бана уже есть на платформе и переиспользуется без изменений.

### 4.4. Информативный попап компании

Заменяет диалог «Тариф». Секции:

1. **Шапка**: название, ИНН, владелец (логин/email), статус-бейдж, долг, просмотры за всё время.
2. **Начисления за период**: предпросмотр позиций (абонплата, просмотры по метрикам, потолок) + кнопка «Сформировать счёт за период» (или надпись «период уже выставлен»). Явно показано, сколько просмотров **идут в счёт** (накоплено за невыставленный период, с разбивкой по метрикам) и сколько **не идут в учёт** (уже в выставленных счетах или набраны до начала биллинга). **Постоплата**: период — календарный месяц от водяной отметки (или его хвост при старте), счёт формируется только после завершения периода; до этого вместо кнопки подсказка «период ещё не завершён — счёт можно будет сформировать после <дата>».
3. **Тариф и статус**: ставки по 5 метрикам + абонплата + потолок, статус (3 варианта), причина скрытия; «Сохранить статус». Поля ставок **автозаполнены** значениями по умолчанию из настроек (или индивидуальными компании); ставки сохраняются автоматически при вводе, начисления выше пересчитываются на лету; пустое поле — вернуть значение по умолчанию.
4. **Счета компании**: последние 10 (номер, период, статус, сумма) с печатью `InvoicePrint` + ссылка «Все счета — во вкладке “Счета и акты”».
5. **Акты компании**: последние 10 с печатью `ServiceActPrint`.
6. В шапке — быстрые действия: «Скрыть контакты» / «Вернуть контакты» / «Доступ» (если нет владельца).
7. **Заметки**: поле ввода + «Добавить», список заметок с датами, удаление отдельной заметки (с подтверждением).
8. **Владелец**: дата регистрации владельца, статус аккаунта (Активен / Забанен), кнопки «Заблокировать» (с причиной) / «Разблокировать»; при создании владельца — кнопка «Сгенерировать пароль», пароль показывается один раз с «Скопировать».

Секции 2–8 — раскрывающиеся (клик по заголовку); по умолчанию открыта только «Начисления за период». Кнопка «Сформировать счёт за период» видна только для активных компаний.

## 5. Что НЕ меняется

- Вкладка «Счета и акты» — механика формирования (диалог предпросмотра), действия, печать, акты.
- Вкладка «Метрики» (журнал просмотров), «Настройки и подарки».
- Расчёты (`src/lib/billing.ts`): ставки, индивидуальный потолок компании, пропорциональная абонплата, нумерация `СЧ-2026-XXX` / `АКТ-2026-XXX`.
- Санкции, приглашения по ссылке, самостоятельная регистрация компаний, ЛК компании (кроме удаления баннера «Приостановлен» и замены блока «Период и начисления» на «Предстоящий счёт за период» — платформа ничего не выплачивает, компания платит сама).
- Печатные формы `InvoicePrint`, `ServiceActPrint`.
- Бан-механика платформы (роут `POST /api/admin/users/[id]/ban`, поле `banReason`, экран для забаненных) — только подключается к попапу компании.
- Выдача доступа владельцу через роут `POST /api/admin/companies/[id]/owner` (режимы link/create/invite) — остаётся, дорабатывается только показ пароля.
